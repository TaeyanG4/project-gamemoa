# 위키/사이트 번역 지침 (GUIDE — 변하지 않는 문서)

**경로**: `docs/i18n-content/GUIDE.md`

이 문서는 **규칙과 절차**만 담습니다. 어떤 파일이 번역됐는지/안 됐는지 같은 **진행 상황은
[`STATUS.md`](./STATUS.md)에 있습니다** — 그쪽은 작업이 끝날 때마다 갱신되지만, 이 문서는 원칙이
바뀌지 않는 한 수정되지 않습니다.

> **한국어(ko-KR)가 항상 원본(source of truth)입니다.** en-US/ja-JP/zh-CN은 전부 한국어를
> 번역한 결과물이며, 콘텐츠를 새로 쓰거나 의미를 바꿀 때는 항상 한국어부터 먼저 확정하고 나머지
> 3개 언어를 그에 맞춰 번역합니다. 반대 방향(다른 언어를 먼저 고치고 한국어를 나중에 맞추는 것)은
> 하지 않습니다.

> **번역을 매번 직접 할 필요는 없습니다.** 새 콘텐츠(신규 페이지/문서 등)를 추가할 때 4개 언어를
> 전부 즉시 번역하는 게 기본값이 아닙니다 — 한국어 원문만 먼저 이 폴더에 정리해두면, 운영자가
> 별도의 저렴한 LLM으로 나중에 일괄 번역해 `.en-US.json`/`.ja-JP.json`/`.zh-CN.json` 형태로
> 가져다줍니다(이미 완료 파일들에 쓰인 방식과 동일). 코드에 연결하는 작업(다국어 파일을
> `dictionary.ts`에 병합하고 라우트에 배선하는 것)은 여전히 필요하지만, 4개 언어 문구를 직접
> 작성하는 과정은 생략해도 됩니다 — 번역 대기 상태로 남겨두고 `STATUS.md`에 ⏳로 기록하세요.

## 폴더 목적

이 폴더는 OwOGG 위키·정책 문서·게임 카탈로그에서 다국어 처리가 필요한 콘텐츠 **전체**를 모아둔
곳입니다. "번역 대기 중인 것"뿐 아니라 **이미 번역 완료돼서
`apps/web/app/features/i18n/dictionary.ts`에 들어가 있는 것도 포함**합니다 — 나중에 문구를
고치거나 지울 때 2,500줄짜리 `dictionary.ts`를 직접 뒤지지 않고 이 폴더만 보고 판단할 수
있도록 하기 위해서입니다.

## 최신화 상태 확인 (자동 도구)

`dictionary.ts`에 이미 들어간 위키 콘텐츠는 나중에 한국어 원문만 수정되고 en/ja/zh 3개 언어가
그대로 방치되는 걸 사람이 매번 기억해서 잡기 어렵습니다. 그래서 마지막으로 4개 언어가 서로
맞다고 확인된 시점의 한국어 원문 스냅샷을 `ko-source-snapshot.json`에 저장해두고, 아래 명령으로
현재 한국어 원문과 자동으로 비교합니다.

```
pnpm i18n:sync-check
```

- ✅ 전부 일치 → 최신화 필요 없음
- ⚠️ **한국어 원문이 스냅샷과 다른 키 목록**이 출력됨 → 그 키들의 en-US/ja-JP/zh-CN이 예전
  한국어 문구 기준일 수 있으니, `dictionary.ts`에서 해당 키의 3개 언어를 새 한국어 원문에 맞게
  다시 확인/수정해야 함
- 수정 완료 후 `pnpm i18n:sync-check --write`로 스냅샷을 새 상태로 갱신

**스냅샷 파일(`ko-source-snapshot.json`)은 코드 파일이 아니라 상태 기록용**이라 직접 수정하지
말고, 항상 `--write` 플래그로만 갱신하세요.

## 이 폴더를 다시 쓰는 시나리오

- **문구 수정**: `STATUS.md`에서 ✅로 표시된 완료 파일에서 원하는 언어의 값을 고친 뒤, 그 파일의
  경로/키를 알려주시면 `dictionary.ts`의 해당 위치에 반영하고 배포하겠습니다.
- **문구 삭제/페이지 삭제**: 마찬가지로 알려주시면 `dictionary.ts`와 실제 라우트 파일(`.tsx`)
  양쪽에서 함께 제거합니다 — 한쪽만 지우면 타입 에러가 나서 안전장치 역할도 합니다.
- **번역 대기 파일 번역 완료 시**: 아래 지침대로 언어별 파일을 만들어 이 폴더에 추가해주시면,
  코드에 연결한 뒤 `STATUS.md`의 "완료" 목록으로 옮기고 원본 대기 파일은 정리하겠습니다.

## 번역 지침 (⏳ 대기 파일용 — 다른 LLM에게 그대로 전달하세요)

1. **원문 언어**: 한국어(ko-KR). **번역 대상**: en-US(영어), ja-JP(일본어), zh-CN(중국어 간체) 3개.
2. **출력 형식**: 각 소스 파일과 **완전히 동일한 키 구조**를 유지한 채, 값만 번역한 JSON을
   언어별로 하나씩 만들어주세요. 예를 들어 `01-wiki-discord.json`을 번역하면:
   - `01-wiki-discord.en-US.json`
   - `01-wiki-discord.ja-JP.json`
   - `01-wiki-discord.zh-CN.json`
     세 파일을 각각 만들어주세요. 키 이름(예: `title`, `step1`, `calloutStrong`)은 절대 바꾸지 말고
     값(문자열)만 번역하세요.
3. **어조**: 서비스 공식 문서 톤 — 격식은 있지만 딱딱하지 않게, 불필요한 수식어 없이 명확하게.
   한국어 원문의 어조를 그대로 재현하면 됩니다 (반말/과도한 이모지 없음). 이미 번역된
   `translated-*.json` 파일들의 en/ja/zh 값을 참고 톤으로 삼으면 일관성 유지에 도움이 됩니다.
4. **절대 번역하지 말 것 (원문 그대로 유지)**:
   - `/owogg`로 시작하는 슬래시 커맨드 전체 (`/owogg link`, `/owogg play game:reaction-time` 등)
   - `<code>...</code>`로 감싸인 코드/명령어/파일 경로 (예: `pnpm discord:commands:check`)
   - 숫자, 수식, 단위 (예: `100 × (L − 1)²`, `+10 XP`, `15분`)
   - `PUBLIC`/`UNLISTED`/`PRIVATE` 같은 상태값 리터럴
   - 브랜드명 `OwOGG` (그대로 유지, 번역/음역하지 않음)
5. **문장 분할 키 주의**: 일부 키는 `xxxPrefix` / `xxxStrong` / `xxxSuffix` / `xxxLink` / `xxxMid`
   패턴으로 한 문장이 여러 키로 쪼개져 있습니다. 이건 코드에서 `<b>`나 `<Link>` 같은 강조/링크
   태그를 문장 중간에 끼워 넣기 위한 것입니다. **각 조각을 독립적으로 번역하되, 이어 붙였을 때
   자연스러운 문장이 되도록** 하세요. 언어마다 강조 위치가 다를 수 있으니(특히 일본어/중국어는
   어순이 다름), 억지로 한국어 어순을 따르지 말고 해당 언어에서 자연스러운 위치에 강조가 오도록
   조각을 구성해도 됩니다 — 다만 원본에 있던 정보 하나하나는 빠짐없이 어딘가의 조각에 포함되어야
   합니다. (완료된 `translated-*.json` 파일들에서 실제 적용 예시를 볼 수 있습니다.)
6. **배열(commands 등)**: `01-wiki-discord.json`의 `discordCommands.commands`는 객체 배열입니다.
   배열 순서와 개수를 그대로 유지하고, 각 객체의 `purpose`/`where`/`args`/`commonError` 값만
   번역하세요. `name` 필드(`/owogg link` 등 커맨드명)는 번역하지 마세요.
7. **완료 후**: 번역된 JSON 파일들을 이 폴더에 그대로 추가해서 알려주시면, `dictionary.ts`에
   병합하고 각 위키/게임 페이지를 실제로 연결하겠습니다.

## 게임 콘텐츠(`02-game-content.json`)에 대한 별도 주의사항

번역이 끝나도 바로 배포에 쓸 수 없습니다 — `GameManifest` 타입이 `title: string`처럼 단일
문자열이라 언어별 전환 구조 자체가 코드에 없습니다. 번역 완료 후 매니페스트 스키마에 로케일별
필드를 추가하는 작업이 별도로 필요합니다(작은 작업이지만, 위키처럼 dictionary.ts에 바로
꽂아넣을 수 있는 나머지 파일들과는 다릅니다).

## 법률 문서 주의사항 (`03-terms-privacy.json`)

번역 후 반드시 사람이 한 번 검수하는 걸 권장합니다. 특히 "개인정보 항목"/"수집 목적" 리스트는
실제 DB 스키마와 대조해 작성된 정확한 내용이므로 의미가 바뀌지 않도록 주의해서 번역해주세요.
