# GAMEMOA 다국어(i18n) 아키텍처

이 문서는 GAMEMOA의 4개 언어 지원 구조(로케일 해석 순서, 저장 방식, 번역 사전 구조, 확장 방법)를
설명합니다. 이 문서 자체를 포함해 저장소 문서(`docs/`)는 계속 한국어로 유지합니다 — 문서 번역은
이번 스코프에 포함되지 않습니다.

## 1. 지원 로케일

| 로케일  | 언어     | 비고   |
| ------- | -------- | ------ |
| `ko-KR` | 한국어   | 기본값 |
| `en-US` | English  |        |
| `ja-JP` | 日本語   |        |
| `zh-CN` | 简体中文 |        |

`zh-TW`(번체 중국어)는 이번 스프린트 범위 밖입니다. 지원 목록은
`packages/core/src/domain/i18nPolicy.ts`의 `SUPPORTED_LOCALES`가 단일 소스이며,
`packages/contracts/src/i18n.ts`의 `SupportedLocaleSchema`가 (다른 플랫폼 enum들과 같은 관례로)
독립적으로 동일한 값을 미러링합니다.

## 2. 아키텍처 선택: 가벼운 내부 타입 사전

`i18next`/`react-i18next` 같은 기존 라이브러리 대신 작고 타입-안전한 내부 사전 시스템을
선택했습니다.

- 새 의존성/락파일 변경이 필요 없습니다.
- `Dictionary` 인터페이스(`apps/web/app/features/i18n/dictionary.ts`)가 키 구조를 강제하므로,
  한 로케일에서 키가 누락되면 빌드 타임에 타입 에러가 발생합니다(문자열 키 오탈자로 인한 런타임
  누락 위험이 없음).
- `useI18n()` 훅이 `dict`(현재 로케일의 번역된 객체)를 그대로 반환하므로 컴포넌트는
  `dict.nav.login`처럼 자동완성 가능한 필드로 접근합니다 — 문자열 경로(`t("nav.login")`) 방식이
  아닙니다.

## 3. 로케일 해석 순서

`apps/web/app/features/i18n/I18nContext.tsx`의 `I18nProvider`가 아래 순서로 해석합니다.

1. 인증된 사용자의 서버 저장 로케일(`user.locale`, `GET /api/auth/me` 응답에 포함)
2. 게스트/현재 브라우저의 `localStorage`(`gamemoa_locale` 키)
3. `navigator.languages`와 지원 로케일의 매칭(`packages/core`의 `matchBrowserLocale` — 정확한
   `en-US` 매칭을 우선 시도하고, 없으면 `en` 같은 언어 코드만으로도 매칭)
4. `ko-KR`(기본값)

로그인한 사용자가 저장된 로케일이 없으면(`user.locale === null`), 현재 로컬/브라우저 선호도를
1회 채택해 서버에 저장합니다(요구사항 원문의 "adopt current preference once" 규칙) — 매 로그인마다
반복되지 않도록 세션 내 1회로 제한합니다.

## 4. 저장 방식

- **인증된 사용자**: `users.locale`(마이그레이션 `0017_user_locale.sql`, nullable — "저장된 적
  없음"과 "명시적으로 ko-KR 선택"을 구분). `POST /api/profile/locale`로 갱신하며,
  닉네임/국가와 달리 **쿨다운이 없습니다** — 언어 전환은 즉시 반영되어야 합니다.
- **게스트**: `localStorage`("gamemoa_locale")에만 저장.

유효하지 않은/지원하지 않는 값(`resolveLocale`)은 항상 안전하게 `ko-KR`로 대체되며, 서버에도 절대
저장되지 않습니다(`isSupportedLocale` 검증).

## 5. 언어 선택기

`apps/web/app/components/ui/LanguageSelector.tsx` — 접근성 있는 `<select>` 기반 선택기이며
현재 Footer(전역 하단, 게스트 포함 모두에게 노출)에 배치되어 있습니다. 언어 변경은 페이지 새로고침
없이 즉시 적용되며, `document.documentElement.lang`도 함께 갱신됩니다
(`I18nProvider`의 `useEffect`).

## 6. 번역 커버리지 (현재 상태 — 정직하게 기록)

실제로 번역을 적용한 범위(누적):

- 전역 헤더(검색 placeholder, 즐겨찾기, 로그인/로그아웃, 사용자 드롭다운 메뉴)
- 전역 푸터(전체)
- 홈 화면의 "미니게임 라인업" 섹션 제목
- 언어 선택기 자체
- **로그인 모달**(제목/부제/닫기/Google·Discord 버튼 및 로딩·미설정 문구) — `dict.loginModal`
- **게임 카탈로그**(`/games`: eyebrow/제목/게임 수 문구/검색창/빈 상태 2종) — `dict.games`
- **랭킹**(`/ranking`: 3개 메인 탭 라벨, 전체 종목/전체 플랫폼 필터, 게임 점수/경험치 모드 전환,
  테이블 헤더 전부, 로딩/에러/재시도, 3개 탭 각각의 빈 상태, 1/2/3위 배지 텍스트) — `dict.ranking`
- **프로필**(`/profile`: 탭 전환, 가입일, 로그아웃, 즐겨찾기/최근 플레이/도전과제 섹션 제목 및 빈
  상태 — 닉네임/국가 편집 폼, 연동 계정 표시, Creator 채널 인증 등 세부 마이크로카피는 스코프 밖)
  — `dict.profile`
- **Discord Hub**(`/discord`: 히어로, 5개 CTA 버튼, 관리 서버 목록, 주간 서버 랭킹 위젯, 이용
  안내, 계정 연동 카드 전체) — `dict.discord`
- **Discord 설치 가이드**(`/discord/setup`: 5단계 전부, 배지 상태 라벨) — `dict.discordSetup`
- **Discord 이용 가이드**(`/discord/guide`: 히어로, 3단계 카드, 설치/계정연결 가이드, 서버 등록
  안내, XP 계산 방식, 명령어 표, 랭킹/문제해결 가이드, FAQ 4문항, 푸터) — `dict.discordGuide`
- **Discord 서버 디렉토리**(`/discord/servers`: 검색, 등록 모달 전체 흐름, 빈 상태) —
  `dict.discordServers`
- **Discord 서버 공개 페이지**(`/discord/servers/:slug`: 에러/로딩 상태, 요약 카드, 리더보드 3탭,
  메타 정보 카드) — `dict.discordServerSlug`
- **Discord 서버 관리**(`/discord/servers/:slug/manage`: 설정 폼, 가시성 선택, 위험 구역, 해제
  확인 모달) — `dict.discordServerManage`
- **Discord 계정 연동**(`/discord/link`: 로딩/무효/에러/성공/확인 5개 상태 전부) — `dict.discordLink`

**아직 사전에 연결하지 않은 화면**(다음 세션 대상): 프로필의 닉네임/국가 편집 폼과 Creator 채널
인증 섹션 등 세부 마이크로카피, Wiki 본문(18개 서브 라우트), Admin 로그인 흐름/센터. `common`
섹션(loading/error/retry/empty/save/cancel)이 이미 정의되어 있어 위 화면들은 새 사전 키를 추가하지
않고도 바로 연결할 수 있는 상태입니다.

라우트 `meta()`(페이지 title/description)는 React Router의 정적 함수라 훅에 접근할 수 없어
이번 스코프에서 로케일화하지 않았습니다 — 필요 시 별도 로더/컨텍스트 전달 방식 검토가 필요합니다.

## 7. 번역 품질 원칙

- 브랜드/제품명(GAMEMOA, Discord, XP, Creator, Featured Creator, YouTube, CHZZK, SOOP, Twitch)은
  번역하지 않습니다.
- 내부 enum/식별자(role, status, platform, API 값)는 번역 문자열과 완전히 분리되어 있으며,
  번역된 표시 문자열이 권한 판단이나 DB 값으로 절대 사용되지 않습니다.
- 숫자는 가능한 경우 `Intl.NumberFormat`/`toLocaleString()`을 사용합니다(예: XP 표시).

## 8. 확장 방법

1. `Dictionary` 인터페이스(`dictionary.ts`)에 새 키를 추가합니다.
2. 4개 로케일 객체(`ko-KR`/`en-US`/`ja-JP`/`zh-CN`) 모두에 값을 채웁니다 — 하나라도 빠지면
   타입 에러가 발생해 즉시 드러납니다.
3. 컴포넌트에서 `const { dict } = useI18n();`로 가져와 사용합니다.
4. 새 지원 로케일을 추가하려면 `packages/core/src/domain/i18nPolicy.ts`의
   `SUPPORTED_LOCALES`와 `packages/contracts/src/i18n.ts`의 `SupportedLocaleSchema`를 함께
   갱신해야 합니다(둘 중 하나만 바꾸면 타입/런타임 불일치가 생깁니다).
