# OwOGG 게임 제작 지침 (초안 — DRAFT)

> **이 문서는 임시 초안입니다.** 유저 게임 제작·등록 시스템 자체가 아직 만들어지지 않았습니다
> (설계/타당성 조사 단계 — `docs/WORK_PROGRESS.md`의 관련 작업 항목 참고). 시스템이 실제로
> 구축되면 이 문서도 함께 개정됩니다. 지금은 "만들어진다면 어떤 규칙으로 운영할 것인가"를
> 미리 정리해 둔 것이며, 아래 수치·기준은 전부 잠정치입니다.

## 1. 누가 게임을 만들 수 있나요

- **인증된 사용자만** 참여할 수 있습니다. 구체적인 인증/권한 부여 기준은 별도로 정합니다 —
  로그인만 되어 있다고 자동으로 자격이 생기지 않습니다.
- 참여 자격이 있어도 **모든 제출은 사람이 직접 검토**합니다. 자동 승인은 없습니다.

## 2. 어떤 형태의 게임까지 만들 수 있나요

> **2026-08-14 확장성 점검으로 확정됨** (`docs/ARCHITECTURE.md` 3.1절): 현재 아키텍처는 게임 1개당
> pnpm 워크스페이스 패키지 1개 구조라, 사용자가 대규모로 제출하는 카탈로그에는 구조적으로 맞지
> 않습니다. 즉 아래 "설정 기반 변형" 방식은 단순히 안전한 선택지가 아니라, "무수히 많은 게임"을
> 실제로 감당하기 위한 **필수 전제조건**입니다.

### ✅ 가능 (1단계 대상)

기존 4개 게임 엔진(반응속도/기억력/에임/타자)의 **파라미터 변형**입니다 — 코드를 새로 짜는 게
아니라 설정값만 바꾸는 방식입니다.

- 난이도 곡선 (라운드 수, 제한 시간, 목표 개수 등)
- 텍스트/문구 (타자 게임의 지문, 안내 문구 등)
- 색상/테마/에셋 (타겟 모양, 배경, 아이콘)
- 점수 계산에 영향을 주지 않는 범위의 표시 방식 조정

### ⚠️ 가능은 하나 대규모 투자가 필요 (당장은 아님)

- 사용자가 직접 작성한 **새로운 게임 로직(코드)**. 브라우저에서 임의 코드를 실행하려면
  iframe 샌드박스 + 엄격한 CSP + 격리 인프라가 필요합니다. 이 단계가 열리더라도 승인은
  자동화되지 않고, 사람이 코드를 직접 검토합니다.

### ❌ 현재는 불가능

- **실시간 멀티플레이어** 게임. 서버 권위 로직·치팅 방지·WebSocket 인프라가 필요해서 제작
  권한만으로는 안 되고, 매번 운영자 백엔드 작업이 필요합니다. 심사 기준도 일반 게임보다
  훨씬 엄격합니다.
- 네이티브 바이너리, 파일 시스템 접근이 필요한 게임 (브라우저 샌드박스 자체의 한계).

## 3. 리소스 제한 (잠정)

- **무료 사용자**: 게임 등록 **1개**, 용량 제한 있음 (정확한 수치는 추후 확정).
- **유료 사용자 (월 $5, 잠정)**: 월간 등록 가능 게임 수와 용량 한도 증가.
- 정확한 가격/한도는 실제 비즈니스 모델 확정 시 이 문서에 반영합니다.

## 4. 승인 전 상태는 어떻게 보이나요

- 승인되기 전까지는 **제작자 본인에게만** "내 게임"으로 표시됩니다.
- 다른 사용자에게는 승인 전까지 전혀 노출되지 않습니다 (검색/카탈로그/공유 링크 전부 비공개).
- 심사 결과는 Creator 심사 시스템(수동 심사 큐, 감사 로그)과 비슷한 방식으로 기록될 예정입니다.

## 5. 콘텐츠 정책 (기본 원칙)

- 불법 콘텐츠, 혐오/차별적 표현, 성인 콘텐츠 금지.
- 타인의 지식재산권(IP)을 침해하는 에셋/텍스트 사용 금지.
- 악성 코드, 다른 사용자에게 피해를 주는 로직 금지.
- OwOGG의 전체적인 톤/브랜드와 크게 어긋나지 않아야 합니다.

## 6. 다음 단계

이 문서는 유저 게임 제작·등록 시스템의 실제 설계/구축이 진행되면서 계속 업데이트됩니다.
현재 단계에서 확정된 것은 "사람이 직접 승인", "인증된 사용자만", "승인 전 비공개",
"무료/유료 티어 구분" 네 가지 원칙뿐이며, 나머지 세부 사항(정확한 용량 수치, 심사 SLA,
콘텐츠 신고 절차 등)은 시스템 설계 단계에서 함께 확정합니다.
